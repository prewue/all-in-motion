# Motion tokens — the shared scale

One scale for every value, so the whole product settles on a handful of clocks. Ships in `assets/motion-tokens.css` (hand-authored) and `assets/motion-springs.css` (generated by `scripts/spring.py --tokens`). Load tokens first, springs second. The same data is in `assets/motion.ts` for JS.

**Core doctrine: match on usage, never on the nearest number.** A 300ms modal close maps to `--motion-quick` (150ms) because both are "modal close", even though the numbers differ. If a value's usage matches no token, leave it alone. Never force a swap because a number is close.

---

## Durations

| Token | Value | Usage |
| --- | --- | --- |
| `--motion-instant` | `0ms` | keyboard-initiated, 100+/day actions |
| `--motion-stagger` | `40ms` | per-item stagger offset |
| `--motion-micro` | `80ms` | tooltip intent delay, shake leg, path-draw delay, large stagger |
| `--motion-quick` | `150ms` | button press, dropdown/modal close, text swap, tooltip appear, checkbox fill |
| `--motion-fast` | `250ms` | dropdown/modal open, icon swap, tabs slide, page slide, accordion, morph close |
| `--motion-medium` | `350ms` | toast in, panel close, toggle travel, morph open, like pop |
| `--motion-slow` | `400ms` | panel open, skeleton reveal, input clear, sheet drag settle |
| `--motion-deliberate` | `500ms` | drawer/sheet (iOS curve), success check, text reveal, badge appear, emphasis |
| `--motion-expressive` | `800ms` | marketing hero, onboarding, one-time moments |

Per-element budget:

| Element | Duration |
| --- | --- |
| Button press feedback | 100–160ms |
| Tooltips, small popovers | 125–200ms |
| Dropdowns, selects | 150–250ms |
| Modals | 200–300ms |
| Drawers / sheets | 500ms (iOS curve makes it feel faster than it is) |
| Panels sliding into a region | 350–400ms |
| Marketing / explanatory | 500–1000ms |

Rules of thumb: UI stays under 300ms. A 180ms dropdown feels more responsive than 400ms. Faster spinners make loading feel faster. Smaller elements animate faster than larger ones. Mobile can go 25–40% shorter (smaller distances). Exits run 60–75% of enter duration.

## Easings

| Token | Value | Usage |
| --- | --- | --- |
| `--ease-out` | `cubic-bezier(0.22, 1, 0.36, 1)` | **default**: enter, exit, open, close, slide, resize, position change. (`cubic-bezier(0.23, 1, 0.32, 1)`, another common strong ease-out, is the same family — equivalent.) |
| `--ease-out-expo` | `cubic-bezier(0.16, 1, 0.3, 1)` | big surfaces, spinning counters, when the start must snap |
| `--ease-out-quart` | `cubic-bezier(0.25, 1, 0.5, 1)` | softer decel |
| `--ease-in-out` | `cubic-bezier(0.77, 0, 0.175, 1)` | on-screen movement: carousel, tab indicator, reorder, drag-and-drop settle |
| `--ease-swap` | `ease-in-out` | in-place cross-fades: icon swap, text swap, skeleton reveal, text reveal |
| `--ease-drawer` | `cubic-bezier(0.32, 0.72, 0, 1)` | native iOS sheet / drawer curve, with 500ms |
| `--ease-hover` | `ease` | hover colour / fill changes only |
| `--ease-linear` | `linear` | shimmer, marquee, progress, spinner, hold-to-confirm fill |
| `--ease-exit` | `cubic-bezier(0.4, 0, 1, 1)` | pure fade-away exits (unfold-out, badge close). The only sanctioned ease-in. |
| `--ease-bounce` | `cubic-bezier(0.34, 1.36, 0.64, 1)` | entrance pop: badge, number pop-in, check bob |
| `--ease-bounce-strong` | `cubic-bezier(0.34, 3.85, 0.64, 1)` | hover-out return (avatar group) |
| `--ease-overshoot` | `cubic-bezier(0.34, 1.56, 0.64, 1)` | playful / marketing / celebration only |
| `--ease-emphasized` | `cubic-bezier(0.05, 0.7, 0.1, 1)` | Material 3 emphasized decelerate, for MD3 parity |

Decision order: entering/exiting → ease-out · moving on screen → ease-in-out · hover colour → ease · constant motion → linear · default → ease-out. **Never `ease-in` on UI**: it starts slow, delaying the exact moment the user is watching. Built-in `ease-out` is too weak for deliberate motion — use the custom curve.

Need a curve not listed? Take it from easing.dev or easings.co; do not hand-roll one.

## Springs (generated, `--spring-<name>-duration` / `-easing`)

Twenty presets measured from a production macOS app's motion system, SwiftUI-style `response` + `dampingFraction ζ`, mass 1. Each ships as a settle duration plus a CSS `linear()` curve, and as stiffness/damping for libraries. Reduced-motion collapses bouncy ones to short ease-outs (already in the CSS).

| Preset | Use it for | r / ζ | k · c | Settle | Overshoot | Reduced |
| --- | --- | --- | --- | --- | --- | --- |
| `state` | **the default**: toggles, selection, filters, list changes, content swaps | 0.27 / 1.0 | 541.5 · 46.5 | 397ms | 0 | unchanged |
| `open` | anything opening/entering: modal, popover, dropdown, toast, drawer | 0.47 / 0.76 | 178.7 · 20.3 | 606ms | 2.5% | spring 0.3/1.0 (441ms) |
| `close` | the same surfaces closing, no bounce | 0.54 / 0.90 | 135.4 · 20.9 | 720ms | 0.1% | spring 0.3/1.0 |
| `hover` | hover colour/fill on buttons, links, cards, rows | 0.40 / 0.85 | 246.7 · 26.7 | 558ms | 0.6% | easeOut 140ms |
| `hoverQuick` | tiny icon hover, pressed colour | ease-out 100ms | — | 100ms | 0 | unchanged |
| `hoverScale` | grow of a clickable badge/pill (1.08) | 0.36 / 0.90 | 304.6 · 31.4 | 480ms | 0.1% | easeOut 120ms |
| `cardHover` | small lift/scale of a card | 0.24 / 0.80 | 685.4 · 41.9 | 324ms | 1.5% | unchanged |
| `press` | pointer down (follows the hand) | 0.14 / 0.82 | 2014 · 73.6 | 193ms | 1.1% | unchanged |
| `release` | pointer up, springing back | 0.24 / 0.74 | 685.4 · 38.7 | 302ms | 3.1% | unchanged |
| `drag` | element following the pointer | 0.10 / 0.90 | 3948 · 113 | 134ms | 0.1% | unchanged |
| `pressSnap` / `pressSettle` | two-phase press | 0.18/0.62 · 0.24/0.78 | — | 294 · 317ms | 8.3 · 2% | unchanged |
| `surfacePress` / `surfaceRelease` | a large surface under a held press | 0.24/0.82 · 0.34/0.68 | — | 330 · 561ms | 1.1 · 5.4% | easeOut 160/180ms |
| `segmented` | chosen option in a segmented control / chips | 0.22 / 0.90 | 815.7 · 51.4 | 294ms | 0.1% | easeOut 160ms |
| `tabSelect` | indicator sliding under a tab | 0.34 / 0.82 | 341.5 · 30.3 | 467ms | 1.1% | easeOut 160ms |
| `emphasis` | a choice that should feel decided, favourites | 0.28 / 0.72 | 503.6 · 32.3 | 450ms | 3.8% | easeOut 200ms |
| `bounce` | playful confirmed click (the only deliberately playful spring) | 0.18 / 0.56 | 1218 · 39.1 | 360ms | 12% | easeOut 200ms |
| `morph` | a control changing width/shape in place | 0.42 / 0.90 | 223.8 · 26.9 | 560ms | 0.1% | easeOut 180ms |
| `panelSlide` | sidebar or inner panel sliding | 0.32 / 0.90 | 385.5 · 35.3 | 427ms | 0.1% | easeOut 180ms |

Choosing: start from `state`. Opens take `open`, the same thing closing takes `close`. Pointer input: `press` down, `release` up, `drag` while dragging (these keep their spring under reduced motion because they follow the user's own hand). `bounce` never on layout. Display tuning: native apps often stretch durations ×1.1 on 75–99Hz and ×1.18 on 60Hz so frame stepping stays invisible; leave web tokens as is unless you deliberately target 60Hz (`spring.py R Z --scale 1.18`).

Generic Motion-style presets when a library takes duration + bounce:

```js
{ type: "spring", duration: 0.5, bounce: 0.2 }   // Apple-style: easier to reason about
{ type: "spring", duration: 0.45, bounce: 0 }    // production default
{ type: "spring", stiffness: 300, damping: 30 }  // mouse-follow interpolation
```

Feel table for stiffness/damping libraries:

| Feel | Stiffness | Damping | Settle | Use |
| --- | --- | --- | --- | --- |
| Gentle | 100–150 | 15–20 | ~500ms | page transitions, modals |
| Default | 200–250 | 20–25 | ~350ms | general, buttons |
| Snappy | 350–500 | 25–30 | ~200ms | toggles, tabs |
| Bouncy | 300–400 | 8–12 | ~600ms | celebrations only |
| Stiff | 500+ | 30+ | ~150ms | cursor following, direct manipulation |

Keep bounce 0.1–0.3 in UI; reserve visible bounce for drag-to-dismiss and playful moments.

## Distances, scales, blur, stagger

| Token | Value | Usage |
| --- | --- | --- |
| `--move-micro` | 4px | text swap |
| `--move-small` | 6px | error shake leg; digit roll uses 7px |
| `--move-base` | 8px | badge slide, page slide, stagger items, dropdown lift |
| `--move-medium` | 12px | text reveal, input clear fly |
| `--move-large` | 30px | success badge appear (banner stacks rise 60px) |
| `--scale-press` | 0.97 | `:active` on any pressable (0.95–0.98 range) |
| `--scale-modal` | 0.96 | modal open/close |
| `--scale-dropdown` | 0.97 | dropdown/popover/toast open |
| `--scale-tooltip` | 0.98 | tooltip open |
| `--scale-closing` | 0.99 | dropdown close |
| `--scale-min-enter` | 0.9 | never enter below this; never `scale(0)` |
| `--scale-hover-lift` | 1.02 | card grow |
| `--scale-hover-grow` | 1.08 | pill/badge grow (1.06 chips) |
| `--scale-pop` | 1.15 | press bounce peak |
| `--blur-small` | 2px | panel reveal, icon/text swap, skeleton reveal, toast, blur bridge |
| `--blur-medium` | 3px | page slide, text reveal, reel spin |
| `--blur-large` | 8px | success check, materialising element |
| `--blur-max` | 14px | fold transitions; never above ~20px |
| `--stagger-fast/base/slow` | 30/40/80ms | keep offset × count under ~300ms |

Travel distance scales *down* with frequency and *up* with ceremony. A pre-scale below ~0.9 reads as a zoom and rarely fits UI chrome. Blur is for softening a swap or slide, never on a plain fade or a colour/theme change; it can also be *missing* where the usage calls for it (a page slide with no blur lane → add `--blur-medium`).

## Naming in other systems

If the project already has tokens, map by usage rather than renaming:

| all-in-motion | common `--duration-*` scales | Material 3 | Tailwind v4 `@theme` |
| --- | --- | --- | --- |
| `--motion-quick` 150 | `--duration-quick` | `short3` 150 | `--duration-quick` |
| `--motion-fast` 250 | `--duration-fast` | `medium1` 250 | `--duration-fast` |
| `--motion-medium` 350 | `--duration-medium` | `medium3` 350 | `--duration-medium` |
| `--motion-deliberate` 500 | `--duration-very-slow` | `long2` 500 | `--duration-deliberate` |
| `--ease-out` | `--ease-smooth-out` | `emphasizedDecelerate` (≈) | `--ease-out` |
| `--ease-in-out` | — | `emphasized` | `--ease-in-out` |

Tailwind v4 registration:

```css
@theme {
  --ease-out: cubic-bezier(0.22, 1, 0.36, 1);
  --ease-in-out: cubic-bezier(0.77, 0, 0.175, 1);
  --ease-drawer: cubic-bezier(0.32, 0.72, 0, 1);
  --duration-quick: 150ms;
  --duration-fast: 250ms;
}
/* → transition-transform duration-fast ease-out */
```

JSON export for design-system tooling is in `assets/motion-springs.json`; the scalar tokens are simple enough to keep in CSS as the source of truth.
